|---|---|

## 气象和污染相似性

对齐的是起报相对时间或目标日提前量，绝对日期不同也能比较。模式来源和统计口径保留在特征键中。

| 特征组 | 输入与处理 |
|---|---|
| 污染初态 | PM2.5、PM10、O3最近24小时均值；后12小时相对前12小时的均值变化；均值至少12个有效小时，变化的每半段至少6小时 |
| 逐日气象 | 风速、风向正余弦、日最大边界层、相对湿度、降水、最高温、云量 |
| 天气形势 | GFS/IFS分别保留；海平面气压、500hPa高度、925/850/700/500hPa风矢量、温湿度、垂直运动、层间温差和短波辐射 |
| 天气系统位置 | 已识别低压、高压、槽、脊中离城市最近的信号，其相对城市的东西/南北近似距离及强度 |
| 浓度指导 | 同一来源、污染物、统计口径在相同提前量上的值；保留缺测，不插值补齐 |
| 背景 | 年内日期的周期编码；有资料时的海拔和盆地指数 |

天气形势当前采样起报相对 -24、0、12、24、48、72、96、120 小时，限于当前预报范围。
原附件的高频序列仍可通过原有形势工具查阅。此版本不是完整格点场相似度检索；最近系统信号
也不是连续追踪的同一个天气系统。距离是相对位置近似，不是输送轨迹长度。

地下气压层被屏蔽，层间温差只使用两个都在地面以上的层次。少数气压层不能识别浅薄逆温的底高、厚度；
日最大边界层高度不能代表夜间最低混合层。更密的近地温度廓线和小时边界层应随数据重建补齐。

检索距离：

1. 各共同特征的绝对差除以固定尺度，每项截断至3；
2. 每组内取均值，再在可比的组间等权平均；
3. 加上当前特征在历史记录中缺失的比例。

至少需要6个共同特征、50%当前特征覆盖、污染初态特征，以及气象/形势/指导中的至少一组。
`pollutant`只筛选初态与浓度指导，气象和背景仍参与比较。相似距离不是概率，尺度没有经过预测增益验证。
归一尺度见 `src/sitian/analogs.py`、`src/sitian/analog_synoptic.py`，构建产物记录这些实现的文件身份。

## 时间和切分边界

- 当前案例的未来真值、专家文本、真值分层标签和气候态均不参与相似度特征提取。
- 历史案例必须明确属于训练集，且起报、全部目标日早于当前起报。
- 整个历史预报期的验证资料必须在当前起报前已可获得，查询使用严格小于号。
- 无逐记录发布时间时，采用最后目标日次日12:00北京时间作为保守可验证时刻；已记录的更晚发布时间或修订时间会进一步推迟可用时刻。
- 查询详情也执行同样的门禁。未知、未到可用时刻、当前 case ID 和路径字符串均不能绕过门禁。
- 建库要求训练清单以及完整的验证、测试、选择集排除清单，按城市—目标日清除交叠。排除清单只读取 case 元信息，不读取其真值。
- 明确的 `historical_event_id`用于过程去重；没有它时，对同城市相隔不超过一个预报期的起报做窗口去重。这只是保守近似，不能声称已识别完整污染过程。

已验证历史结果可以给 Agent 看，用于判断经验是否适用。当前案例未来结果仍只供评分器使用。
历史详情没有发布预报时明确返回 `not_recorded_in_case_contract`，不把隐藏的专家预报冒充历史发布预报。
CAMS 的三小时瞬时O3日最大与目标八小时日最大不同：质量视图报告口径不一致，历史详情不把二者差值标为同口径误差。

## 方法卡来源

内置6张卡：稳定与扩散持续、冷空气清除、上游输送、指导冲突、臭氧条件、历史类比适用性。
它们都是明确标记 `common_sense / hypothesis` 的设计假设，**本轮没有导入真实JJJ_ATMO专家卡**。

可通过 `FH_FORECAST_METHODS`指定独立JSON库，顶层为 `contract_version`和`cards`。
卡片结构参考 `src/sitian/forecast_methods.py` 中的 `BUILTIN_CARDS`；不接受额外的原始案例字段。
JJJ_ATMO来源要求 `source_kind=JJJ_ATMO`、`review_status=reviewed`、`source_refs`、`reviewer`、
`reviewed_at`、带时区的`source_available_at`及`case_answers_removed=true`；源材料必须早于当前起报。
代码可验证这些声明的结构和时间，但不能自动证明人工摘要已彻底移除案例答案，仍需内容审核。
未来接入真实语料方法卡须作为新信息集冻结并评估，不能沿用旧协议的“语料不进入输入”实验身份。

检索采用确定性的中文二元词片段/英文词重合，不调用向量服务。无匹配返回不可用；卡中需要但未注册的工具会显式列出。
方法卡可以引用为 `expert_prior`，不赚取可验证数据的grounding奖励。

## 配置与建库

```bash
.venv/bin/python scripts/build_historical_case_index.py \
  --train-manifest /path/to/final_train.json \
  --exclude-manifests /path/to/val.json /path/to/test.json /path/to/selection.json \
  --out /path/to/new_history.json

export FH_HISTORICAL_CASE_INDEX=/path/to/new_history.json
# 不设置FH_FORECAST_METHODS时使用内置常识卡；设置FH_METHOD_RETRIEVAL=0可做无方法检索对照。
.venv/bin/python scripts/build_verl_tool_config.py \
  --case /path/to/case_with_eligible_history --out /path/to/new_tools.yaml
```

建库拒绝覆盖现有输出。方法库和历史索引身份进入任务简报和新生成的工具配置；
veRL回放会拒绝工作进程与配置之间的资源身份不一致。历史索引需显式配置，不自动选择旧数据目录。
独立推理与训练工作进程应使用相同环境变量。配置变化后必须重新生成工具配置、任务输入并冻结实验身份。

本轮基于修复快照的3061条训练清单构建了开发验收索引：
`data/interim/harness_v2_20260912/historical_cases.json`。
排除清单为完整有效val、test以及冬季选择集；原训练清单已做目标日隔离，因此新增清除为0。
此产物只证明建库与工具可运行，不代表暂停清单中的数据问题已解决，也不是新训练已就绪的声明。
