# 9800X3D 本机原始数据检查与重建交接

## 目标与机器分工

Precision 7960 训练主机已有已构建 case 和修复后的数据副本，但没有挂载原始资料盘。
外置硬盘在用户的 9800X3D 本机。应在该本机先核实原始资料，再在独立工作目录重建。
“训练主机当前没有原始资料”不等于“原始资料丢失”。

本次目标是找出未构建原因、恢复能可靠构建的 case，并产出有来源记录的新数据版本。
数据不满足观测有效性时继续隔离，不降低有效小时数要求，不用插值或合成值冒充真值。

## 四种不同的问题

1. **代码错误，已修复**：空间聚类的 pm10/pm10_primary 不一致；CAMS 风向文字映射偏移。
   修复脚本为 scripts/repair_data_snapshot.py；八方位函数为 src/sitian/meteorology.py。
   新聚类有105城的PM10主导特征非零，最终8个留城成员恰好未变化。
2. **原抽样案例未构建，需要找原始资料核对**：总计752个，全部属于原 train。
   2025-04有147个、2025-05有578个、2026-02有27个。原构建日志汇总为CAMS缺失725个、
   观测不足27个；没有逐case失败日志，不能仅凭这两个汇总认定每个case的失败原因。
3. **已建案例被有效性检查隔离，不等于未构建**：491个，train/val/test分别444/19/28。
   只有发现真实原始文件缺失、损坏或存在更完整合法版本后才重新验收，不能直接放回。
4. **研究设计与资料口径限制，需要独立处理**：冬季训练偏少，CAMS缺D5，O3瞬时日最大
   与目标八小时滑动均值日最大不同，测试事件窗口高度重叠。找回外置盘不能自动解决这些问题。

## 当前数据规模

原计划train/val/test为6000/800/1500，共8300个城市—起报日。
已建5248/800/1500，共7548个正式case；另有1个独立smoke case。
隔离491个后，有效清单为4804/781/1472，共7057个。
在有效train内再做冬季时间缓冲和整城留出后，实际RL train为3061个。
这些数字口径不同；不能将“7057到3061的差额”全部解释成数据丢失。

## 本机优先查找的资料

| 资料 | 常见路径或文件模式 | 核查重点 |
|---|---|---|
| CAMS地面浓度及气象场 | raw/cams/sfc_YYYY-MM-DD_YYYY-MM-DD.nc | PM2.5/PM10、风、边界层、温湿、降水、云量；实际时次和lead |
| CAMS O3模式层资料 | raw/cams/o3_YYYY-MM-DD_YYYY-MM-DD.nc | O3变量、模式层137、实际时次/lead/单位 |
| 原始城市小时观测 | raw/aq_obs/cities/YYYY/china_cities_YYYYMMDD.csv | 目标城市列、六项小时污染物和O3_8h、有效小时覆盖 |
| 派生日值库 | aq_daily.sqlite | 来源、日期与城市覆盖；旧库不是原始小时资料的替代品 |
| 开放形势/成分/火点等证据 | sitian_open_evidence/{raw,derived,manifests} | case附件所需issue是否齐全、来源SHA和available_at |
| 北方补充模式 | eaget/keti_data/{cmaq,naqp}/day | 城市、前日20时起报、有效日期；保持原信息集可比 |

盘上有NetCDF不等于缺失资料已补齐：应实际打开文件，检查变量、时间轴、区域、有限值、
压缩/下载是否完整。多个文件可能覆盖相同日期；不能只依赖文件名或“文件非空就跳过”。
O3三小时瞬时序列不能直接当作真实八小时指标；任何由插值得到的指导必须标注近似。

## 补建752个case的最小日期范围

以现有 unbuilt_episodes.json 为准，共33个不同起报日：

- 2025-04-25至2025-05-22；2025-05-28至2025-05-29；2026-02-05至2026-02-07。

CAMS使用**起报日前一天12 UTC**的预报循环，需要核查33个reference date：

- 2025-04-24至2025-05-21；2025-05-27至2025-05-28；2026-02-04至2026-02-06。

观测输入读取起报日前3天至起报日07时，五天真值覆盖起报日+1至+5。因此原始城市
观测至少需要以下54个日期的文件（具体城市和字段仍需逐case核查）：

- 2025-04-22至2025-06-03；2026-02-02至2026-02-12。

以上只是补建752个case的最小范围；复核491个隔离case、重建全部气候态或城市选择
可能需要更广的历史资料，不能用这个最小范围宣称整个数据源已经完整。

## 执行顺序

1. 识别9800X3D的操作系统、项目位置、外置盘挂载点。先列目录及文件覆盖，不修改原盘。
2. 找到上述资料和旧manifest/log/SHA sidecar；生成原始文件清单，并与缺失城市—起报日匹配。
3. 逐case将原因分为：路径未配置、日期缺失、文件损坏、变量/时次错误、原始观测有效性不足。
   列出缺少哪些文件、可否从盘上恢复、是否需要重新下载，保留证据。
4. 在独立工作目录使用已修正的代码。先抽查不同缺失月份的case，确认时间门禁、单位、
   风向和日值正确，再批量补建；输出每个case的成功或失败原因。
5. 重新做观测有效性审计，挂接相应日期的开放证据，记录恢复了多少有效case及剩余缺口。
   必须保留原始采样清单和冻结测试；不能为改善结果重新随机切分。
6. 下一版如重设冬季选择块，先审查完整过程/月份覆盖、未来目标城市日隔离，再冻结新协议。
   原选择集已经参与开发，不能直接回流训练并沿用旧验证结论。
7. 用最终新train重建历史偏差索引、全部输入身份和Parquet。所有对照使用相同新信息版本；
   确认新版本验收完成后，才安排训练主机的数据切换。

现有 build_daily_all.py --rebuild 会删除目标位置旧数据库，build_national_case.py 会跳过
已有truth.json的case；若直接对原目录运行，可能破坏快照或误以为旧case已经重建。
因此先确认路径/输出目录支持，必要时补充显式输出参数，在独立目录运行，不对原盘和冻结
训练目录直接执行重建。

  challenge_winter.json 及相关冻结manifest；需要按原身份核对。

不能仅复制本说明而假定这些数据文件也在本机；它们大多不随Git提交，需要单独确认或传输。

## 本机任务启动说明

检查这台9800X3D机器连接的外置硬盘，为司天空气质量Agent RL项目找回原始资料。
先按本交接文档核查CAMS sfc/o3、城市小时观测、aq_daily.sqlite、开放证据和缺失日期，
输出逐case缺失原因与可恢复范围。随后在独立目录使用已修复代码重建可恢复case，重新
执行有效性、时间门禁和来源身份检查。保留原盘、原case、冻结切分和训练主机当前实验；
不降低数据有效性标准，不用合成真值补缺，不将恢复文件数量冒充有效训练case数量。
